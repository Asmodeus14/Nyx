================================================================================
Nyx OS — GPU / 3D Engine Evolution
Intel Gen9.5 (Comet Lake, device 0x9BC4, GT2) — RENDER Command Streamer (RCS)
================================================================================

This document tracks the bring-up of a full 3D rendering engine on the Intel
integrated GPU, driving the RENDER command streamer (RCS) and the Gen9 3D
pipeline in legacy ring-buffer mode (no execlists / GuC), culminating in a
mini-GL API exposed to userspace over syscalls.

Target: Intel Comet Lake iGPU, PCI device 0x9BC4 (GT2), mapped to
GpuGeneration::Gen9. Tested on bare metal only (QEMU cannot emulate the render
engine); every 3D milestone is verified over serial + on-panel photo.

--------------------------------------------------------------------------------
GVA (GGTT) MEMORY MAP owned by the 3D engine
--------------------------------------------------------------------------------
Chosen to avoid the BLT driver's existing allocations (ring 0x1000_0000,
backbuffer 0x1400_0000, fence 0x1500_0000, windows 0x2000_0000+).

  0x1600_0000  RCS ring buffer
  0x1700_0000  Batch buffer(s)
  0x1800_0000  Instruction base (shader kernels)
  0x1900_0000  Dynamic state (viewport / CC / blend / sampler)
  0x1A00_0000  Surface state + binding tables
  0x1B00_0000  Vertex / index buffers
  0x1C00_0000  Depth buffer
  0x1D00_0000  Textures
  0x1E00_0000  RCS fence / scratch

--------------------------------------------------------------------------------
HARD-WON LESSONS (first-triangle bring-up) — avoid this whole bug class
--------------------------------------------------------------------------------
The first triangle took THREE distinct root-cause bugs, all the same shape: a
Gen9 field whose innocent-looking or "more complete" value is the trap. When a
field is left 0 or set to the seemingly-safe option, cross-check Mesa's Gen9
lowering (ELK, not brw — brw is Xe/Gen12+) and the local genxml before trusting
it.

  Bug #1  EU hardware opcodes. mov=1 / send=49 (pre-Xe). We had mov=2 (=sel!) and
          send=51 (=sends, split-send) — silently mis-encoded every instruction.
          Symptom: VS_inv>0 but CL_inv=0, deadlock.

  Bug #2  3DSTATE_RASTER Cull Mode. Value 0 = CULLMODE_BOTH (cull EVERY triangle),
          NOT "none". CULLMODE_NONE = 1. An all-zero DW1 culls everything.
          Symptom: CL_prims=1 but PS_inv=0, black screen.

  Bug #3  PS Render-Target write must be HEADERLESS on Gen9. Setting header-present
          and forwarding raw R0/R1 as the message header fed the render cache
          garbage (PS payload is NOT in RT-write-header format) -> per-thread
          garbage destination addresses -> wild, per-boot-varying GGTT page faults
          while PS_inv>0. Mesa builds a header only for dual-source / multi-RT /
          kill, and even then it is a constructed g0-derived header, never a raw
          forward. The render cache derives each pixel's destination from the
          fixed-function dispatch; the EOT pixel mask comes from the exec mask.

Debug infrastructure that made this tractable:
  - On-device command-stream decoder (render/decode.rs) prints the whole batch
    as readable lines, so one screen photo captures the pipeline.
  - Staged PIPE_CONTROL "progress" fences: the fence page holds the last stage
    reached, so a hang is localized without a GPU debugger.
  - Fault-address readback: GEN8_FAULT_TLB_DATA0/1 (0x4b10/0x4b14) decode the
    exact faulting GPU virtual address; RING_FAULT_REG = 0x4094.
  - Gen9 pipeline-statistics MMIO counters pinpoint where a draw dies:
    IA_VERTICES 0x2310, VS_INVOCATION 0x2320, CL_INVOCATION 0x2338,
    CL_PRIMITIVES 0x2340, PS_INVOCATION 0x2348. (IA_VERTICES needs a separate
    3DSTATE_VF_STATISTICS enable to count — IA_verts=0 is a red herring.)
  - MOCS table MUST be programmed on Gen9 (all entries LLC write-back) or render-
    cache writes have undefined caching and never reach memory.

--------------------------------------------------------------------------------
Phase 6: 3D Primitives, Transforms, and Depth  ->  spinning depth-tested cube
--------------------------------------------------------------------------------
Objective: go from one hardcoded NDC triangle to real indexed geometry with a
model-view-projection transform and a working depth buffer.

Reference: PRM vol07-3d_media_gpgpu.pdf; genxml 3DSTATE_INDEX_BUFFER,
3DSTATE_DEPTH_BUFFER, 3DSTATE_WM_DEPTH_STENCIL, 3DSTATE_CLEAR_PARAMS.

Actionable Steps:

1. Index buffers.
   - Implement 3DSTATE_INDEX_BUFFER (index format UINT16/UINT32, GGTT address at
     0x1B00_0000 region) and switch 3DPRIMITIVE to RANDOM (indexed) access.
   - Add a vertex-format abstraction so a mesh declares its attributes
     (position, color, later normal/uv) and the code emits matching
     3DSTATE_VERTEX_ELEMENTS / VERTEX_BUFFERS automatically.

2. CPU-side math (new engine/math.rs).
   - mat4 (multiply, identity), perspective (fovy/aspect/near/far), lookAt,
     translate/rotate/scale, vec3/vec4.
   - START by transforming vertices on the CPU: feed already-projected clip-space
     verts to the existing pass-through VS. This isolates the math from the VS
     kernel and reuses the proven Phase-5 pipeline unchanged.

3. Move the transform into the VS (push constants).
   - Upload the MVP matrix via 3DSTATE_CONSTANT_VS (push-constant region already
     reserved by PUSH_CONSTANT_ALLOC_VS) into the VS payload GRFs.
   - Extend the VS kernel with multiply-add (mul/mad) ops to transform position
     by the MVP. Validate the new EU encoding by byte-diff vs Mesa ELK as in
     Phase 3. Keep the CPU-transform path as a fallback for A/B debugging.

4. Real depth buffer.
   - Allocate + GGTT-map a depth surface at 0x1C00_0000 (D32_FLOAT or D24_UNORM),
     replace the SURFTYPE_NULL 3DSTATE_DEPTH_BUFFER with a real one, program
     3DSTATE_CLEAR_PARAMS, and clear it each frame.
   - Enable depth test LESS + depth write in 3DSTATE_WM_DEPTH_STENCIL. HiZ can
     stay off initially.

5. Animation loop.
   - Drive rotation from a frame counter / TSC; re-emit the MVP push constant per
     frame; re-run the pipeline; present.

Milestone: a spinning, depth-tested, per-vertex-colored cube on the monitor.
Watch for: back-face occlusion correct (depth working), no z-fighting, cull mode
now meaningfully BACK (test that CULLMODE_BACK culls the correct faces).


--------------------------------------------------------------------------------
Phase 7: Textures & Samplers  ->  textured cube
--------------------------------------------------------------------------------
Objective: sample a 2D texture in the pixel shader.

Reference: PRM vol02b (SURFACE_FORMAT), vol07 (sampler messages); genxml
RENDER_SURFACE_STATE, SAMPLER_STATE, 3DSTATE_SAMPLER_STATE_POINTERS_PS.

Actionable Steps:

1. Texture upload.
   - Allocate + GGTT-map texture storage at 0x1D00_0000; upload pixels; clflush.
   - Start LINEAR (no tiling) to reuse the Phase-4/5 surface path; add Y-tiling
     later for performance.

2. Texture surface state.
   - Build a second RENDER_SURFACE_STATE (sampled image, e.g. R8G8B8A8_UNORM),
     place it as binding-table entry [1] (RT stays entry [0]).

3. Sampler state.
   - Build SAMPLER_STATE (min/mag filter, wrap modes), place in dynamic state,
     point 3DSTATE_SAMPLER_STATE_POINTERS_PS at it.

4. Textured PS kernel.
   - Add UV as a second vertex attribute; the SF interpolates it into the PS
     payload (extend 3DSTATE_SBE attribute count + read offset).
   - New PS variant: issue a sampler `send` (SFID sampler) with the UVs, receive
     the RGBA result, then the headerless RT write. Byte-diff the new send vs
     Mesa ELK sampler lowering.

Milestone: a textured, spinning cube.


--------------------------------------------------------------------------------
Phase 8: Engine API Layer
--------------------------------------------------------------------------------
Objective: wrap the raw command emission behind a small, reusable engine so
scenes are described in data, not hand-rolled batches.

Actionable Steps:

1. engine/ module.
   - Device (owns the RenderEngine + state allocators), Buffer, Texture,
     Shader (selects a compiled kernel), Pipeline / render-state, CommandList.
   - draw_indexed(mesh, material, mvp); present().

2. Scene helpers.
   - Mesh (vertex/index buffers + format), Camera (view/proj), Transform,
     Material (shader + textures + render state).

3. Present path.
   - Currently proof-of-life copies the backbuffer to scanout then holds. Replace
     with a proper present: either the existing BLT-to-scanout swap, or a true
     display flip via PLANE_SURF register writes (the driver currently only reads
     those regs — add the write path) for tear-free double buffering.
   - Resolve backbuffer ownership vs the compositor: the engine should render into
     its own surface and composite, not fight the window server for 0x1400_0000.

Milestone: a scene (multiple meshes, a camera) rendered from data through the
engine API, presented without the Phase-5 "present + 5s hold" hack.


--------------------------------------------------------------------------------
Phase 9: Mini-GL + Syscalls + Userspace Demo  (stated end goal)
--------------------------------------------------------------------------------
Objective: expose the engine to userspace as a small OpenGL-like API over
syscalls, and prove it with a userspace 3D app.

Reference: existing GPU syscall model in nyx-kernel/src/interrupts.rs
(syscalls 501-513; sys_swap_buffers = 502). Add new syscalls at 514+.

Actionable Steps:

1. Syscall surface.
   - Define syscalls: create/destroy buffer, create/destroy texture, create
     shader/program, bind, set uniform (MVP etc.), draw(_indexed), clear, present.
   - Marshal handles (not raw kernel pointers) across the boundary; validate all
     userspace-supplied sizes/offsets in the kernel (no GGTT address escapes).

2. Mini-GL library (userspace).
   - Thin libGL-like wrapper over the syscalls: glGenBuffers/glBufferData,
     glGenTextures/glTexImage2D, glUseProgram, glUniformMatrix4fv, glDrawElements,
     glClear, glSwapBuffers.

3. Userspace demo app.
   - Patterned on apps/compositor: open the device, upload a cube, spin it,
     present each frame — entirely from userspace through the mini-GL API.

Milestone: a userspace process rendering an animated 3D scene through mini-GL
syscalls.

Stretch (only if multi-app 3D is required):
   - Per-process GPU contexts need PPGTT (only GGTT exists today) and most likely
     execlists. A single-context mini-GL runs fine on GGTT; scope PPGTT/execlists
     only when two apps must render concurrently.
